### Probe verdicts (design §2.2) — run offline via `spike/Spike.MafDeclarative` (`dotnet run -- probes`)

- **PROBE-A (structured MCP result) — PASS, with a corrected form.** A tool result whose single `TextContent` is a JSON **object** string does **not** crash and is **not** typed to `Double`. **Finding (decompiled `InvokeMcpToolExecutor.AssignResultAsync`):** the executor runs `JsonDocument.Parse` on each `TextContent`; a valid JSON **object** parses into a PowerFx **record**, collected into a **one-row table**. So fields are read directly as `First(Local.x).field` (e.g. `First(Local.locate).path`) — **NOT** via `.Value`. The `.Value` single-column accessor only appears for a result string that is **not** valid JSON (the spike's `"5 words"`). **⇒ FEAT-003/004 YAML must read structured MCP results as `First(Local.x).field` record access, and `ParseJSON` is NOT needed** (the executor already parses). This supersedes the design §5.2/§9.2 "`ParseJSON(First(Local.x).Value)`" form.
- **PROBE-B (read a step output back to the host) — PASS.** The host can recover a named `Global.*` variable from run state by running with checkpointing: `CheckpointManager.CreateJson(new FileSystemJsonCheckpointStore(dir))` passed to `InProcessExecution.RunStreamingAsync(workflow, input, checkpointManager, …)`. The persisted checkpoint stores each variable under a scope key `"<actionId>|@Global|<name>"` with its serialized value (confirmed: `capture_path|@Global|locatePath` = `"src/Checkout.cs"`). **⇒ the seam (`MafRunDriver`) surfaces step outputs via the committed explicit-`Global.<stepId>`-variable path and reads them from the checkpoint/run-state; there is no per-action output event needed.** (`SuperStepCompletedEvent.CompletionInfo.Checkpoint` marks each checkpoint; `StreamingRun` itself only exposes checkpoint accessors, not a direct variable getter.)
- **PROBE-C (`ParseJSON`) — ABSENT; fallback form is mandatory.** `ParseJSON` is **not** available in the 1.27.0 declarative PowerFx host (`'ParseJSON' is an unknown or unsupported function`). Malformed/non-JSON tool results surface as a plain string via the `.Value` single-column table (no crash, no blank — the run continues). **⇒ The §9 input-shaping fork resolves to the NON-`ParseJSON` form:** subject/body are supplied as named trigger arguments (`MapInput` → `Global.subject`/`Global.body`) and the support YAML is authored against `Global.subject`/`Global.body` (NOT `ParseJSON(System.LastMessage.Text)`). For structured MCP results, use the executor's own JSON parsing + record field access (PROBE-A), not `ParseJSON`. Design §9/§11 text that assumed `ParseJSON` must use this chosen form.

### FEAT-004 declarative-syntax findings (proven in `spike/Spike.MafDeclarative`, `dotnet run -- feat004|agentprobe|endprobe`)

Confirmed while authoring the real module YAMLs against the FEAT-003 seam; recorded so FEAT-005 and future module authors do not rediscover them:

- **`IsMatch` is "recognized but not supported"** in the 1.27.0 declarative PowerFx host. Regex routing is done with `Lower(subject & " " & body)` + `Find("application a", t) > 0 Or Find("applicationa", t) > 0` — faithful to the old `Application\s?A` (optional single space), with every literal lower-cased to match `Lower(...)`.
- **`ParseJSON` absent (confirms PROBE-C):** every field read out of a JSON string goes through the executor's own JSON parse via `First(Local.x).field`. Two built-in seam MCP tools provide this generically: `flowgent.input` (echoes the run input object) and `flowgent.parse` (echoes an arbitrary `payload` string, e.g. an agent's structured answer), both read as `First(Local.x).field`.
- **`InvokeAzureAgent` does NOT surface `inputs`/`inputArguments` (incl. a step id) to the provider.** The only channel is `agent.name`, which accepts a PowerFx expression; the migration carries `"<stepId>|<agentId>"` there, so `MafAgentProvider` keys the Demo response + telemetry step id off the left part and resolves the agent off the right (or the run's dynamically-assigned agent). Support passes the dynamic id via `=Concatenate("resolve|", Local.agentId)`.
- **`GotoAction` jumps to the EXACT action id** and skips intermediate actions, so a branch that must run a terminal's plumbing (`Global.__terminalId`/`__message`/`__finalOutput`) must target that terminal's FIRST `SetVariable`, not its `SendActivity`.
- **`EndConversation`** is required after a terminal's `SendActivity` to stop sequential fall-through into the next terminal block.
- **Step-output surfacing timing:** a step's `Global.<stepId>__detail` must be written BEFORE its `Global.<stepId>` snapshot so both land in the checkpoint the seam reads when it first surfaces the step (the seam marks a step reported on first sight; a later-arriving detail would be missed).
- **Agent calls must use the non-streaming `AIAgent.RunAsync`** (not `RunStreamingAsync`) so the call goes through `IChatClient.GetResponseAsync` where `LlmTelemetryMiddleware` records it (streaming bypasses telemetry).
- **PowerFx checkpoint values are wrapped `{ typeId, value }` recursively** (records and their fields); the seam strips the envelopes at every level before parsing to a `JsonNode`.
- **Graph projection** cannot YamlDotNet-parse the workflow (PowerFx values contain `": "` inside quotes, valid for the declarative builder but not YamlDotNet); `WorkflowProjector` line-scans `- kind:`/`id:` instead and builds nodes from `<stepId>_snapshot` steps + manifest terminals.
